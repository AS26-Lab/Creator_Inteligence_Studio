# Codex Workflow - Creator Intelligence Studio

## Rol

Codex trabaja como implementador del proyecto, no como origen de decisiones no documentadas.

## Reglas operativas

1. Una misión por vez.
2. Cambios pequeños y acotados.
3. Revisar el contexto antes de modificar.
4. No instalar sin autorización.
5. No hacer refactors masivos.
6. No asumir APIs o capacidades no verificadas.
7. Mantener separación entre UI, dominio e infraestructura.

## Flujo de trabajo

1. leer la documentación maestra;
2. revisar el estado del repositorio;
3. identificar la tarea inmediata;
4. modificar el mínimo necesario;
5. verificar el resultado;
6. reportar archivos y comandos;
7. declarar riesgos y pendientes.

## Qué debe reportar Codex

- archivos cambiados;
- comandos ejecutados;
- pruebas realizadas;
- resultados obtenidos;
- riesgos residuales;
- pendientes abiertos.

## Qué no debe hacer sin autorización

- instalar dependencias;
- descargar modelos;
- inicializar bases de datos;
- cambiar configuraciones del sistema;
- ejecutar refactors extensos;
- modificar fuera de la carpeta del proyecto.

## Calidad mínima

- cambios trazables;
- pruebas cuando correspondan;
- mensajes claros;
- documentación alineada con la implementación;
- ninguna suposición silenciosa sobre el entorno.
